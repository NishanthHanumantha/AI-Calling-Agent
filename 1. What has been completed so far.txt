3. Why is this taking time?

The work is more involved than simply sending the same prompt to four LLMs and comparing their text responses.

A. This is a live voice evaluation, not just a text benchmark.
Each model has to work within an actual call flow: customer speech, transcription, model response, spoken output and the next customer turn. A model can perform well in text but still introduce delays, misunderstand speech or disrupt the conversation sequence.

B. The comparison needs to be fair and measurable.
All four models need comparable scenarios, consistent evaluation criteria, traceable transcripts and recordings, and an independent judge. We also need to distinguish a genuine model error from a telephony, transcription or infrastructure issue.

C. Live calls need reliability controls.
A slow model response can leave the caller waiting. The evaluation therefore includes timeout handling, fallback responses, process cleanup and controls to avoid overlapping calls. The configured eight-second model-turn budget is an intended target, not a guarantee that every webhook will respond within eight seconds.

D. Deployment must not disrupt the existing agent.
The production system is already working. The evaluation service is being isolated on port 8001, with its own routes and a separate Nginx path. That adds deployment and verification work, but reduces the risk of affecting production.

E. Each model needs actual live testing.
We must confirm that the model responds correctly over the phone—not merely that its API is reachable—and then inspect the resulting calls before scaling up the evaluation.
