# Version baseline

Version: V3 frozen / V4 development

Baseline purpose: `Version3/` is the frozen working baseline. `Version4/` is the independent development copy for Human-Like Conversation Improvements. Future changes belong only in `Version4/`. Do not modify `Version3/`.

This file records the project as inspected on 5 October 2026, then the confirmed live speech settings synchronized into Version 4. Those settings are configuration and integration choices. The model was not fine-tuned.

## Freeze scope

`Version3/` is a file copy of the current working tree, including the uncommitted `Setup_Instructions.md` update. `app_v3.py` and `make_call.py` match Git commit `0aa297a` ("Update Twilio voice and STT configuration") on `main`.

Not duplicated into either version folder, and still present at the project root:

- `.git` (repository history)
- `venv/` (local virtual environment; recreate from `requirements.txt`)
- `__pycache__/` and `*.pyc` (generated bytecode)

No earlier `Version3/` or `Version4/` folder existed. Existing alternate files `app_v3_backup_20260903.py` and `app_v3_OS1.py` are inside `Version3/` only.

## Project structure

The running application is one FastAPI module plus an outbound script and the brochure. There is no `static/` or `templates/` directory. Production prompts are written inside `app_v3.py`. `app_v3.py` does not import the other application files or `LLM_Evaluation/`.

`Version4/` contains its own copies of:

- `app_v3.py`
- `make_call.py`
- `sobha-townpark-brochure.pdf`
- `requirements.txt`
- `.gitignore`
- `.env` (local file already used by this project; values are not recorded here)
- `README.md`
- `Setup_Instructions.md`
- `LLM_Evaluation/` source, tests, prompts, config, dataset, and empty output placeholders

## Entry points

| Role | File | What the code does |
|------|------|--------------------|
| Application | `app_v3.py` | FastAPI app. `GET` or `POST /voice` starts the call. `POST /handle-speech` receives speech. |
| Outbound call | `make_call.py` | Creates a Twilio call to `{PUBLIC_URL}/voice`. |
| Evaluation | `LLM_Evaluation/` | Separate offline and live-voice evaluation. Live-voice bind in code is `127.0.0.1:8001`. |

## Confirmed live speech configuration

Version 4 now follows the speech configuration confirmed for the live Lightsail deployment. These are integration settings, not LLM fine-tuning.

TTS: Twilio `<Say>` in `say_block()`. Voice: `Polly.Kajal-Neural`, from `TWILIO_SAY_VOICE` in `Version4/.env`.

STT: Twilio `<Gather>` in `gather_block()`. Speech model: `experimental_utterances`. Language: `en-IN`.

LLM: Sarvam `sarvam-105b-conversations`.

`LLM_Evaluation/live_voice/constants.py` still sets `SAY_VOICE = "Polly.Aditi"`. That value is used only by the separate evaluation app, not by `app_v3.py`.

## Current LLM

`app_v3.py` sets `MODEL = "sarvam-105b-conversations"` and `SARVAM_URL = "https://api.sarvam.ai/v1/chat/completions"`. The key name is `SARVAM_API_KEY`. `generate_response()` is called from the FAQ answer path only. The model id was not changed.

## Current STT

Twilio `<Gather>` in `gather_block()` already matched the confirmed live speech settings, so this synchronization did not edit that block:

- `input="speech"`
- `action="https://s-ai-calling-agent.duckdns.org/handle-speech"`
- `method="POST"`
- `speechTimeout="5"`
- `speechModel="experimental_utterances"`
- `language="en-IN"`
- `timeout` from `GATHER_TIMEOUT` (`"30"`)

`correct_stt()` applies stage-based text fixes after Twilio returns `SpeechResult`.

## Current TTS

`<Say>` uses `TWILIO_SAY_VOICE` from the environment. `Version4/.env` sets it to `Polly.Kajal-Neural`. If that variable is missing, the code fallback in `app_v3.py` is still `Polly.Aditi`. The `<Say>` element does not set a language attribute.

## Current RAG source

`BROCHURE_FILE = "sobha-townpark-brochure.pdf"`, loaded with PyMuPDF (`fitz`) from the application directory.

## Current port

`app_v3.py` does not bind a port. `Setup_Instructions.md` documents the local command `uvicorn app_v3:app --host 0.0.0.0 --port 8000`. The live-voice evaluation constants set `EVAL_BIND = "127.0.0.1"` and `EVAL_PORT = 8001`. The Lightsail process supervisor and listen port are not in this repository.

## Evaluation components

`LLM_Evaluation/` includes the offline evaluator, interactive lab, reporting, model clients, tests, `config/models.yaml`, `dataset/golden_dataset.csv`, and `live_voice/`. Its dependency list is `LLM_Evaluation/requirements.txt`. Historical run outputs were not copied into `Version4/`.

## Known current behaviour

`conversation_memory` is one in-process dictionary, reset when `/voice` starts. Stages present in `app_v3.py` include `greeting`, `qualify`, `answer_faq`, `visit_day`, `visit_pick_slot`, `propose_slot`, and `closed`.

The greeting, qualification question, visit-day prompt, slot choice, and closing are fixed TwiML in `app_v3.py`. Brochure answers go through `generate_response()`. Visit slots in code are `10:00 AM`, `11:30 AM`, `4:00 PM`, and `6:00 PM`. `MAX_FAQ_TURNS` is `8`. `MAX_EMPTY_RETRIES` is `3`.

No human-like conversation changes have been made in this copy.
